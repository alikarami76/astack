# Report rules (from the user's corrections — non-negotiable)

1. Lead with the data the user asked for (a table or chart), then the answer in one or two sentences, then what it means for the decision.
2. Plain words for a generalist reader. No jargon, no invented terms, no stacked nouns. If a statistical term is needed, explain it in half a sentence.
3. Every number has its unit, and money has a currency plus a time unit (e.g. "22 bn dollars per month").
4. Every chart is an exhibit. It has, in this order: a number («نمودار ۲»), a title that states the finding as a sentence with a verb, a subtitle that gives the measure, the cuts, the unit (with currency and time unit for money) and the base (population, n, window), then the plot, then notes (what the series include, how numbers are rounded, whether rounded shares add to 100) and a source that names this run and whether the number is verified. One highlight colour marks the thing the title is about; everything else is grey. Values are labelled on the bars and lines, not in a legend. A missing value is shown as «—», never dropped.
   - 4a. Round once per chart: whole numbers above 10, one decimal below. Write «یادداشت: مجموع ارقام به‌دلیل گرد کردن ۱۰۰ نیست» when rounded shares do not add up.
   - 4b. A sentence title must be proved by the numbers it states. If the chart cannot prove the title, change the title; never change the chart to match.
5. Caveats come after the data, at most three, one sentence each, and only the ones that could change the decision.
6. No correction logs, addenda, "update" boxes or warnings. When something changes, fix the deliverable in place.
7. Deliver only what was asked, in the format asked (PDF, xlsx with a sheet per table plus a description column and the queries, dashboard, deck). Open the file for the user.
8. When the user may want to check, include short, simple validation queries they can run themselves.
9. State confidence honestly: say what was verified independently and what rests on an assumption.
10. Reuse the structure of the best previous deliverable of the same kind.

## Recurring report preferences

11. A periodic report's headlines are the KPIs of the product area it covers, not overall business metrics.
12. Never invent a cause, project or name, even in samples. When the cause is unknown, say so plainly.
13. Each report section ends with a short "how it is calculated" glossary; titles are plain.
14. Ask the user for business facts (which tasks finished, rule definitions) instead of inferring them.
